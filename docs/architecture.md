# Pulsewise 的模块边界

Pulsewise 是单进程 macOS 应用。采样与更新各自管理状态，原生宿主和浏览器宿主管理运行环境，面板管理页面与 HTTP 协议。

## 依赖方向

```text
main
  ├─ gui ── panel ── stats
  │    ├─ stats   └─ update
  │    └─ update
  └─ web ── panel
       └─ stats
```

只有 `gui` 可以依赖 Wails。`panel` 不依赖宿主实现，通过它自己定义的 `Host`、`SnapshotSource` 和 `Updates` 接口访问能力。`stats` 和 `update` 不依赖界面或宿主包。

## 调用方式与职责

原生宿主创建采样器和更新器，将它们传给面板：

```go
sampler := stats.NewSampler(time.Second)
updater := update.New(ctx)
handler := panel.Handler(host, sampler, updater)

go sampler.Run(ctx)
go updater.Run()
for snapshot := range sampler.Subscribe(ctx) {
	// 生成图标，并通过 Wails 的 UI 线程提交。
}
```

浏览器宿主传入 `nil` 更新器。这个可选能力只在 HTTP 边界处理，浏览器宿主不需要实现虚假的重启方法。

| 模块 | 管理的职责 |
| --- | --- |
| `stats` | 系统读数、CPU 差值计算、历史、快照和订阅 |
| `update` | 版本判断、更新状态、下载、校验、安装和重启 |
| `panel` | 内嵌页面、HTTP 路由、请求校验和响应 |
| `gui` | Wails 窗口、菜单栏、UI 线程和原生应用生命周期 |
| `web` | HTTP 监听、浏览器宿主和服务器生命周期 |

`stats` 的系统读取函数持有前一次 CPU tick，采样器只消费读数，不负责调用具体的 macOS API。采样器使用私有读取函数注入点进行确定性测试，不公开通用驱动框架。

`Snapshot` 是两个界面共用的读模型，保留现有 JSON 字段。为它再建立一套同形 DTO 不会减少当前的依赖。

## 数据流与生命周期

1. 构造采样器时立即采样，宿主随后启动带 `context.Context` 的采样循环。
2. 每次采样更新缓存及最近 17 个历史点。
3. 每个订阅者有一个容量为 1 的通道。未消费的旧快照会被最新快照替换，采样不等待界面处理。
4. `Latest()` 和每个订阅通道都返回独立的历史切片，调用方修改自己的快照不会污染其他读者。
5. 面板继续每秒读取 `/api/state`，菜单栏通过订阅更新。现有 URL、JSON 字段和图表行为保持兼容。
6. 宿主退出时取消采样、订阅和更新检查。原生退出仍调用 `Quitting()`，尝试安装已下载的更新。

更新器的自动调度和检查请求共享构造时传入的应用生命周期。HTTP 请求结束不会中断已经开始的更新；应用退出会取消请求和下载。

## 设计取舍

这次重构比较了两种结构：

- 集中式应用服务统一转发采样、窗口、HTTP 和更新操作。它提供单一入口，但也让一个对象知道所有模块，且大部分方法只是转发。
- 按职责分包，由宿主组装依赖，面板定义消费端接口，采样器发布有界快照通道。这个结构让状态留在所属模块，也允许不启动 Wails 就测试 HTTP 协议，因此采用此方案。

通道只传递最新状态，不保证交付每一次采样。这适合菜单栏展示，不能直接用于需要完整数据的记录器。采样历史仍由采样器维护，不依赖订阅者是否及时读取。

自动更新的签名检查、安装回滚、退出安装和脱离父进程的重启保留原实现。提交 `95f73c0` 明确记录了这些发布行为；提交 `addeefd` 记录了不加载运行时应用图标以减少内存的原因。

## 验证

运行 `sh tools/check.sh`，执行包依赖检查、竞态测试、静态检查、JavaScript 语法检查，以及真实二进制的浏览器模式检查。依赖检查会阻止核心包反向引用宿主，或在 `gui` 之外引入 Wails。

自动检查不覆盖菜单栏点击、Spaces、全屏窗口和真实签名应用的升级，这些仍需要在 macOS 上手工验证。
